# G-SAVE API 1 新游戏支持包制作教程

## 1. 支持包的职责

支持包只负责两件事：

1. GUI 配置时检测游戏 EXE、进程名和一个或多个存档根目录；
2. Repository Engine 提交时只读解析存档元数据。

支持包不执行 Git、不联网、不启动外部程序，也不写存档。Git 初始化、忽略规则和配置写入由 GUI 完成。

## 2. 最小目录结构

```text
my-game\
├─ manifest.toml
├─ adapter.lua
└─ README.md          可选，建议写清楚自动检测到的目录层级
```

`manifest.toml` 与 `adapter.lua` 是必需文件。ZIP 可以直接包含这些文件，也可以只包含一个顶层目录。

## 3. manifest.toml

```toml
package_api = 1
id = "my-game"
name = "MY GAME"
version = "0.1.0"
adapter = "adapter.lua"
platforms = ["windows"]

[game]
store = "steam"
steam_app_id = 123456
process_name = "MyGame.exe"
executable_relative_path = "Bin/MyGame.exe"

[watch]
include_globs = ["*/Save*.dat"]
exclude_globs = [".git/**", "cache/**", "**/*.bak"]

[git]
exclude_globs = ["cache/**", "**/*.bak", "*.tmp"]
autocrlf = false

[commit]
strategy = "hybrid"
quiet_seconds = 5
max_interval_seconds = 300
commit_on_exit = true
```

关键约束：

- `package_api` 当前必须为 `1`；
- `id` 使用稳定的小写英文、数字和短横线，发布后不要修改；
- `adapter` 必须位于支持包内部；已经有人配置该包后，升级版不要改变适配脚本的相对路径；
- `process_name` 必须与实际 EXE 文件名一致，安装时会校验；
- `watch.include_globs` 相对于 GUI 最终选择的存档根目录；
- `.git/**` 必须排除；
- `git.exclude_globs` 会写入 `.git/info/exclude`，不要忽略真正的存档；
- 二进制存档保持 `autocrlf = false`。

路径匹配规则：`*` 不跨目录层级，`**` 可以跨任意层级，Windows 下忽略大小写。

## 4. install(context)

安装入口必须返回最终检测结果：

```lua
local APP_ID = 123456
local PROCESS_NAME = "MyGame.exe"

function install(context)
    local process_path = context.steam_executable(APP_ID, "Bin/MyGame.exe")
    local repositories = {}

    for _, remote in ipairs(context.steam_userdata(APP_ID)) do
        local save_root = context.path_join(remote, "saves")
        if context.is_directory(save_root)
            and context.is_file(context.path_join(save_root, "Save00.dat")) then
            repositories[#repositories + 1] = {
                path = save_root,
                include_globs = { "Save*.dat" },
                exclude_globs = { ".git/**", "*.bak" },
            }
        end
    end

    local problems = {}
    if process_path == nil then
        problems[#problems + 1] = {
            code = "game_executable_not_found",
            message = "未找到 MY GAME，请确认游戏已通过 Steam 安装",
        }
    end
    if #repositories == 0 then
        problems[#problems + 1] = {
            code = "save_not_found",
            message = "未找到 Save00.dat，请先运行一次游戏",
        }
    end

    return {
        process_name = PROCESS_NAME,
        process_path = process_path,
        repositories = repositories,
        problems = problems,
    }
end
```

安装沙箱可用 API：

- `known_folder("roaming_app_data" | "local_app_data")`
- `steam_executable(app_id, relative_path)`
- `steam_userdata(app_id)`
- `path_join(...)`
- `is_file(path)`、`is_directory(path)`
- `list_directories(path)`、`basename(path)`

选择存档根目录时，先确定哪些文件必须作为一个整体恢复。专用包必须完全依靠 `install()` 自动定位，GUI 不会为专用包提供手动路径选择，因此相对路径规则必须自身完整可靠。
例如匹配 `*/Save.dat` 时，玩家应选择账号目录的上一层；匹配 `Save.dat` 时，应直接选择包含该文件的目录。

## 5. parse(repository, changed_files)

解析入口只能读取仓库内文件并返回可序列化的 Lua table：

```lua
local function normalize(path)
    return path:gsub("\\", "/")
end

function parse(repository, changed_files)
    local save
    for _, path in ipairs(repository:files()) do
        if normalize(path):lower() == "save00.dat" then
            save = path
            break
        end
    end

    local stat = save and repository:stat(save) or {}
    return {
        game_id = "my-game",
        accounts = {{
            account_id = "默认账号",
            slots = {{
                index = 1,
                occupied = save ~= nil,
                character_name = "",
                label = "当前进度",
            }},
            path = save,
            file_size = stat.size,
            modified_unix_ns = stat.modified_unix_ns,
        }},
        changed_files = changed_files or {},
        warnings = {},
    }
end
```

提交沙箱可用 API：

- `repository.path`
- `repository:files()`：仓库内相对文件列表，不含 `.git` 和符号链接；仍需自行过滤目标存档；
- `repository:read(relative_path, offset, length)`：从零开始的范围读取；
- `repository:stat(relative_path)`：返回 `size`、`modified_unix_ns`；
- `repository:md5(bytes)`：仅用于已有存档格式的完整性校验；
- `repository:aes_128_cbc_decrypt(ciphertext, key, iv)`：只读格式解码辅助。

GUI 槽位时间线使用 `accounts[].account_id` 和 `accounts[].slots[]`。每个槽位建议返回：

- `index`：从 1 开始；
- `occupied`：是否有角色；
- `character_name`：无法可靠解析时返回空字符串，不要猜；
- `label`：例如“最近存档”“旅店存档”；
- 可选 `level`、`played_seconds`。

元数据最多 64 KiB，嵌套深度最多 8。遇到未知版本、校验失败或越界时返回 `warnings`，不得修改存档。

## 6. 测试要求

发布前至少完成：

1. Lua 合成数据测试：自动检测成功、检测失败、空槽、满槽、损坏头和越界长度；
2. 真实存档只读解析：确认文件大小、账号数、槽位数和校验结果；
3. 在临时副本中初始化 Git，连续修改两轮，确认每轮只生成一次提交；
4. 确认 `.git`、`.bak`、缓存和配置文件不会触发提交；
5. 恢复测试必须使用副本，不得修改唯一真实存档；
6. ZIP 通过 GUI 实际导入，导入后出现卡片，点击后应自动检测出全部路径；
   检测不完整时必须通过 `problems` 说明原因，不会退回手动选择。

项目内可参考：

- `packages/dark-souls-iii`：BND4、多账号和 10 槽位；
- `packages/elden-ring`：原版/无缝联机、范围读取与 MD5；
- `packages/dragons-dogma-2`：多文件槽位标签；
- `tests/lua/package_adapter_tests.lua`：宿主 API 合同测试。

## 7. 打包与发布

推荐 ZIP 结构：

```text
my-game.zip
└─ my-game\
   ├─ manifest.toml
   ├─ adapter.lua
   └─ README.md
```

限制：最多 512 项，解压后总大小不超过 64 MiB；不得包含符号链接、绝对路径或 `..` 路径穿越。
导入只安装支持包，不运行 `install()`；玩家点击卡片时才检测路径、初始化仓库并写入配置。
